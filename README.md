# HFP+SELCALL

Одна программа для Windows, macOS и Linux, которая умеет два протокола:

- **HFPager** (PS-18, 1.46 / 5.86 / 23.44 / 46.88 Бод): совместимый пейджер из [ra4pvj/HFP](https://github.com/ra4pvj/HFP);
- **HF Selcall** по CCIR 493-4, совместимый с CODAN: индивидуальный вызов и Message call (текст до 64 символов), из [ra4pvj/SELCALL](https://github.com/ra4pvj/SELCALL).

Оба приёмника одновременно слушают **один и тот же звуковой вход**: переключать режимы не нужно. Обе передачи идут через один выход, с тем же уровнем TX и тем же PTT/CAT. Во время любой своей передачи оба приёмника на паузе.

## Запуск

- Windows: `run_hfp_selcall.bat` или `py -m pip install -r requirements.txt` и затем `py hfp_selcall_app.py`.
- macOS: `run_hfp_selcall.command` (первый раз — правый клик → «Открыть»).
- Сборка exe: `build_exe.bat`. Сборка .app: `build_app.sh`. Готовые сборки (Windows x64/x86, macOS arm64/x64, Linux x64) делает GitHub Actions (`.github/workflows/build.yml`) при теге `v*` или ручном запуске с номером версии.

Нужны Python 3.8+ (3.8 — последний для Windows 7), numpy, sounddevice, pyserial.

## Версии

- **v0.2.0** — стабильная версия.
- **v0.3.0-beta…** — предварительные версии (pre-release) с новым окном; выпускаются этапами, после проверки станут стабильными.

## Окно (с версии 0.3)

Вверху всегда видны: лампы RX/TX, индикатор уровня входа (пиковый, dBFS: зелёный ниже −12, жёлтый −12…−3, красный выше −3; перегрузка — 98 % полной шкалы), спектр 300–3000 Гц и электронные часы: UTC и выбранный часовой пояс (MSK +3 и др., или время компьютера).

Вкладки:

1. **Чат** — только общий журнал обмена (главная страница). Фильтр «только мне», очистка окна, журнал TXT.
2. **Новое сообщение / вызов** — поля ID и текста и кнопки для HFPager («Отправить») и HF Selcall («Вызов», «Сообщение»). Символы сверх предела (252 для HFPager, 64 после транслита для Selcall) выделяются красным и не передаются.
3. **HFPager** — свой ID, скорость, тон 0, порог приёма, АПЧ, подтверждения, отложенные сообщения (QRU?).
4. **HF Selcall** — свой Selcall ID, приём, точки, транслит, АПЧ; звонок (тип, длительность, устройство), ответ в эфир, прослушивание эфира, включение внешнего устройства.
5. **Трансивер и аудио** — звуковой вход/выход и канал, уровень TX, задержка PTT; PTT; CAT (частота, режим, диапазоны, шаг, сценарии); внешнее устройство на отдельном COM-порту. В списках COM-портов есть «Выключено».
6. **Программа** — язык (русский / English), тема (светлая / тёмная), часовой пояс вторых часов, папка журнала и отложенных сообщений, о программе.

Меню: «Файл» (журнал, папка, отложенные), «Вид» (тема, язык), «Справка» (инструкция — F1, о программе). Буфер обмена работает во всех полях и в чате (Ctrl/Cmd + C/V/X/A, в том числе в русской раскладке, и меню правой кнопки мыши).

Подробности о Selcall-функциях:

Канал входа (рядом с выбором входа): «авто» выбирает тот канал стерео-интерфейса, где есть сигнал (раньше брался всегда левый). Если вход перестаёт отдавать звук больше 4 с (USB-кодек «уснул», например IC-705), приём перезапускается сам. Это касается обоих приёмников.

Принятые Selcall-вызовы попадают в общий журнал с пометкой `SELCALL`. Вызов или сообщение на свой ID выделяется (вызов **с** вашего же ID тоже считается вызовом; помечается «своя передача» только эхо собственной передачи — тот же адресат и текст в момент вашей передачи), над журналом появляется жёлтая панель «☎ … от NNNN» с кнопками «Ответить» (подставляет отправителя в «Кому» и открывает вкладку Selcall) и «Сбросить», звучит звонок. «Фильтр ID» скрывает и чужие Selcall-вызовы. Всё записывается и в текстовый журнал (`Документы/HFPSelcallApp/messages.txt`).

Настройки хранятся отдельно от HFP и SELCALL: `%APPDATA%\HFPSelcallApp`, `~/Library/Application Support/HFPSelcallApp`, `~/.config/HFPSelcallApp`.

## Файлы

| Файл | Откуда | Что делает |
|---|---|---|
| `hfp_selcall_app.py` | на основе `HFP/hfpager_app.py` | общий Core: звуковой вход для обоих приёмников, передача, PTT; запуск программы |
| `hfp_selcall_gui.py` | новый (0.3) | окно: вкладки, часы, индикатор, тема, язык, буфер обмена |
| `i18n.py`, `i18n_en.py` | новые | перевод интерфейса на английский |
| `help_text.py` | новый | инструкция (RU/EN), меню «Справка» |
| `icon.png`, `icon.ico`, `tools/make_icon.py` | новые | иконка программы |
| `hfpager_modem.py`, `hfpager_rx.py`, `hfpager_ptt.py`, `hfpager_rig.py`, `HFPAGER_PROTOCOL.md` | HFP, без изменений | кодек и приёмник HFPager, PTT, CAT и сценарии |
| `selcall.py` | `SELCALL/python/selcall.py` (0.3.14), без изменений | кодек CCIR 493-4 (`python selcall.py selftest`) |
| `selcall_engine.py` | на основе `SELCALL/windows/hfselcall_win.py` (0.3.14) | потоковый приёмник Selcall на общем входе (передискретизация в 8 кГц), сборка сигнала, звонок и сигнал ответа, прослушивание, внешнее устройство |
| `tests/test_combined.py` | новый | проверка без звуковой карты и без окна |

Модули HFP и SELCALL скопированы без правок, поэтому исправления из исходных репозиториев переносятся простым копированием файла.

## Проверка

```
python tests/test_combined.py   # приём/передача без звуковой карты
python tests/test_i18n.py       # все строки интерфейса переведены
python tests/test_gui.py        # окно целиком на заглушке tkinter (без дисплея)
```

Тест проверяет без звуковой карты и без окна:

- один входной поток содержит кадр HFPager и Selcall-сообщение — оба декодируются;
- передача Selcall (вызов и сообщение) через общий передатчик декодируется обратно;
- реальная запись CODAN `testdata/SELCALL_from_1111_to_1234.wav` декодируется через общий вход на 48 кГц;
- стерео-вход с сигналом только во втором канале: выбран канал 2; один и тот же вызов дважды подряд — два вызова, без дублей; эхо своей передачи и вызов со своего ID различаются;
- ответ в эфир («Калинка» один раз + задержка PTT и хвост), затем прослушивание; ручное «Слушать»; порт PTT/CAT для внешнего устройства не принимается.

**Не проверено:** окно запускалось только с имитацией tkinter. Работа с настоящей звуковой картой, трансивером и CODAN в эфире не проверялась.
